# 一、如何写一个模型训练文件(基于LeNet)
## 1.模型声明
- 声明LeNet，基层torch.nn.Module
- 在__init__函数中调用父类__init__()并定义模型的隐藏层
- 定义forward函数，定义模型的前向传播
## 2.加载数据集
- 1.数据预处理：转为Tensor, 并归一化到[-1, 1]
    - 定义transforms数据转换，ToTensor()、Normalize()等
- 2.下载MNIST训练集和测试集:
    - 可以自己提供数据集或者加载torchvision.datasets中的数据集（MNIST）
- 3.创建数据加载器：
    - 定义数据处理的batch_size
    - 使用torch.utils.data中的DataLoader创建数据加载器
## 3.初始化模型、损失函数和优化器
- 1.初始化模型：
    - 查看是否有gpu并下载cuda，赋值device为cuda或者cpu
    - 将模型加载到cuda或者cpu上(默认cpu)
- 2.损失函数:
    - 因为是多分类任务，所以使用softmax激活函数并使用交叉熵损失函数，因为模型的前向传播最后是全连接，并没有使用激活函数，所以直接定义损失函数为criterion = nn.CrossEntropyLoss()，这个损失函数同时包含softmax激活函数和交叉熵损失函数，将它们放在一起是为了避免复合函数在依次调用时造成的精度损失
- 3.选择优化器：
    -使用torch.optim中的SGD，这是基础的梯度下降函数，同时将模型实例的参数交给优化器，初始化学习率参数、动量参数以及L2正则参数
## 4.训练函数
- 调用model.train(),是声明的dropout层起作用（dropout是设置一个比例，让神经元随机失活，为了防止模型过拟合）
- 记录当前阶段的损失、正确率
- 函数具体过程：
    - 循环训练集数据加载器的分批的数据
    - 将数据加载到device上
    - 使用模型预测结果output
    - 使用criterion计算损失loss
    - 使用优化器清除上一批数据计算的权重向量和偏置的梯度
    - 对loss进行反向传播
    - 使用优化器进行梯度下降
    - 统计相关数据（当前这一批数据的损失是多少、预测的结果、这一批数据的数量、正确预测的数据的数量）
## 5.验证函数
- 调用model.eval(), 让dropout层不起作用
- 记录训练集的损失和正确率
- 函数具体过程：
    - 循环测试集数据加载器的分批的数据
    - 将数据加载到device上
    - 使用模型预测结果output
    - 使用criterion计算损失
    - 统计相关数据（与训练函数的一样）
## 6.训练循环
- 根据设定的spochs进行训练
- 获取每一次的损失和正确率
- 进行每一次的损失和正确率输出

# 二、过拟合和欠拟合
看懂训练集（Train）和测试集/验证集（Val/Test）的 **损失（Loss）** 与 **准确率/指标（Acc/Metric）** 变化，是判断模型是否过拟合（Overfitting）或欠拟合（Underfitting）的核心技能。

可以通过以下**四大经典场景**、**核心指标特征**以及**可视化曲线形态**来精准判断：

---

### 📊 一图总结：四大状态对比

| 状态 | 训练集 Loss | 测试集 Loss | 训练集 Acc | 测试集 Acc | 核心诊断 |
| --- | --- | --- | --- | --- | --- |
| **高水平拟合 (理想状态)** | 低且稳定 | 低且与 Train 接近 | 高 | 高 (接近 Train) | 模型泛化能力极佳 |
| **欠拟合 (Underfitting)** | **高** (降不下去) | **高** | **低** | **低** | 模型太简单，根本没学会 |
| **过拟合 (Overfitting)** | **极低** | **高** (甚至反弹) | **极高** | **远低于 Train** | 模型死记硬背，不会举一反三 |
| **数据泄露 / 评测异常** | 高 | 低 (居然比 Train 好) | 低 | 高 | 逻辑错误或评估代码写错 |

---

### 🔍 1. 如何判断“欠拟合”（Underfitting）？

**本质**：模型连训练集的数据规律都没学会，相当于“没学进去”。

* **数据特征**：
* **Train Loss 很高**：训练了很多个 Epoch，训练集 Loss 依然下降缓慢或者卡在一个较高的位置。
* **Train Acc 偏低**：在训练集上的表现都很差（比如分类准确率只有 60%~70%）。
* **Test Loss 和 Train Loss 一样高**：测试集 Loss 同样降不下来。


* **学习曲线形态（Loss vs Epoch）**：
* 两条 Loss 曲线都处于高位，平缓地贴在一起，无法下降到预期的低位。


* **常见原因与解决方案**：
* **网络太简单/表达能力不足**：增加网络深度或宽度（如增加卷积层、全连接层节点数）。
* **学习率（Learning Rate）设置不当**：太小导致学不动，太大导致无法收敛。
* **训练轮次（Epochs）不够**：模型还没来得及学完，增加训练轮数。
* **特征工程/数据预处理有问题**：数据归一化没做好，或者特征太少。



---

### 🔍 2. 如何判断“过拟合”（Overfitting）？

**本质**：模型把训练集的噪声和细节当成了通用规律，相当于“做过的题能拿满分，换一道题就挂科”。

* **数据特征**：
* **Train Loss 非常低，Test Loss 显著高于 Train Loss**。
* **Train Acc 接近 100%，但 Test Acc 明显滞后/下降**（比如 Train Acc 99.5%，Test Acc 却只有 85%）。
* **出现“拐点”**：随着训练进行，Train Loss 继续下降，但 Test Loss 在下降到某个临界点后，**开始止跌回升（反弹）**。


* **学习曲线形态（Loss vs Epoch）**：
* 训练集 Loss 一路向 0 走；测试集 Loss 先下降，随后向上弯曲反弹（两条线拉开巨大的喇叭口）。


* **常见原因与解决方案**：
* **数据量太少**：进行数据增强（Data Augmentation，如旋转、裁剪、翻转）。
* **模型太复杂/参数量过大**：简化网络，或在全连接层添加 **Dropout**。
* **缺乏正则化**：在优化器中增加 **Weight Decay**（L2 正则化）。
* **训练时间过长**：使用 **Early Stopping（早停法）**，在测试集 Loss 开始反弹的前一刻停止训练。



---

### 🔍 3. 什么是“理想/良好拟合”（Good Fit）？

* **数据特征**：
* Train Loss 和 Test Loss 都降到了合理的低位。
* Test Loss 稍高于 Train Loss（属于正常泛化差距），但**绝对差值极小**，且 Test Loss 保持平稳，没有反弹趋势。
* Train Acc 和 Test Acc 都很高，两者差距保持在很小的区间内（例如 1%~3% 左右）。



---

### ⚠️ 注意事项：避免两个常见的判断误区

#### 误区 1：只要 Test Loss > Train Loss 就是过拟合？

> **纠正**：**错！** 几乎所有模型的 Test Loss 都会略高于 Train Loss（因为测试集是未见过的样本）。只要测试集 Loss 稳定在低位且不反弹，绝对差值微小，就属于正常的泛化差距（Generalization Gap），不叫过拟合。

#### 误区 2：看 Loss 绝对倍数（如“大于 2 倍就是过拟合”）？

> **纠正**：**错！** 在 Loss 数值极小时，倍数会严重失真。
> * **例子**：Train Loss = `0.001`，Test Loss = `0.003`（3 倍差距），但两者的绝对差距只有 `0.002`，此时模型的测试准确率可能高达 99.2%，这绝不是过拟合，而是非常优异的拟合效果。一定要结合**绝对差值**和**测试集 Acc** 来综合评估。
